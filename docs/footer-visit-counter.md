# Footer visit counter

- The Netlify footer shows **Visitor No. :** followed by an approximate aggregate for Play, Guide, About and Privacy starting on publication. A reload is a new load. A quick navigation that aborts the request may not be counted. The game frame is excluded. This isn't a unique-person count, a historical total or an advertising metric.
- The separate, ad-free Google Sites embed is `https://lucy-awakening.netlify.app/trilogy-visit-counter`. Insert it by URL in the Shade trilogy footer; give it roughly 48 pixels of height, then validate that it renders in published Google Sites before calling it live. It counts the embed loads that are actually recorded (Google Sites or browsers may defer offscreen embeds), and uses the same **Visitor No. :** label. Direct top-level requests show the current total without adding a visit.
- The raw measured totals start from zero in distinct keys in the existing Netlify site's Blob store. The public display uses a starting count of 343 for Netlify and 400 for the Shade trilogy, documented here and, for Netlify, in Privacy. These are starting values, not historical measurements. Each counted load displays the starting count plus the previously recorded loads, then persists the current load. Reading the Google widget directly shows all recorded loads plus 400 without incrementing. The code keeps totals only, with no identifiers, cookies, local storage or analytics service. Netlify still handles normal hosting/security requests; the counter endpoint has platform rate limiting per IP and domain. This discourages bursts but doesn't guarantee bot exclusion.
- Preview, unpublished and noncanonical requests never touch production storage. Verify the deploy preview, dependency build and rate-limit rules in the deploy log. Then verify the deployed footer in a normal browser and the Google embed on the published Google site. Each actual production navigation while verifying can add a page load; opening the Google counter URL directly is read-only.
- Both surfaces add ordinary Netlify requests (one POST per Netlify page plus a cacheable script, or one Google embed request) and Blobs reads/writes. Storage consists of two numbers, but request and invocation allotments depend on the existing team plan. This does not require a new service, upgrade, or billing setting change.
